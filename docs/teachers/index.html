LEIA for teachers

This guide explains every screen, button and field that a teacher meets while designing a LEIA, running it with students and reviewing the results. Read this page first. It introduces the vocabulary and the two applications, and it tells you which page of the guide answers each task.

Which version is described

Due to updates some features may suffer minor changes.

What a LEIA is​

A LEIA is an AI assistant that plays a role in a learning activity. It can be the client you interview to discover requirements, the opponent in a guessing game, a tutor that watches you code, or any other character a teacher imagines. Students talk to it in writing or by voice, and at the end they may submit a solution that LEIA grades.

Every LEIA is assembled from three reusable components.

ComponentWhat it holdsExample
PersonaWho the character is. Name, description, personality and pronouns.Helen Park, the manager of a small university library
BehaviourHow the character acts during the conversation. This text becomes the instructions the language model follows.An interviewee who answers questions but never volunteers a full solution
ProblemThe learning task. The statement the student sees, hidden details, the reference solution, the solution format and the evaluation instructions.Discover the requirements of a room booking system and model them as a UML class diagram

A LEIA is the combination of one persona, one behaviour and one problem, saved under a name and a version. The same persona can appear in many LEIAs, and the same problem can be played by different characters.

The two applications​

ApplicationURLWho uses itWhat you do there
Designerdesigner.leia.ovhTeachersDesign and test LEIAs, group them into activities, manage API keys and labels
Workbenchworkbench.leia.ovhTeachers and studentsTeachers create replications, configure how each LEIA runs, watch live sessions and review results. Students join with a code and talk to the LEIA

The same account works in both applications. Students never need an account. They enter the Workbench with an email address and the code of the replication.

More vocabulary​

TermMeaning
ActivityA group of one or more LEIAs prepared in the Designer for a class. The Workbench calls activities experiments. An activity must be published before the Workbench can see it, and a published activity cannot be changed any more.
ReplicationOne run of an activity in the Workbench. It has its own join code, its own switches (active, repeatable, time limit, language) and its own results. You can create as many replications of a published activity as you need, one per class group for instance.
SessionOne student working on one replication. A session has a transcript, an optional submitted solution, an evaluation and a score.
LabelA coloured tag you attach to LEIAs to find them later in the library.
WidgetAn extra panel the student sees next to the chat, such as a code editor that LEIA can read, edit and test. Widgets are part of the problem.
SupervisorA second, private AI that watches the conversation and flags behaviours you asked it to watch for. It can also send a short nudge to the student.
Transcription modeA LEIA inside an activity that shows a pre-written conversation instead of letting the student talk. Useful for analysis exercises.
MultiLEIAAn activity where several LEIAs take part in the same conversation, for example a client and an IT manager in one meeting.

The life of a LEIA​

  1. Design. Describe the activity to the AI assistant or start from an existing LEIA. Adjust the persona, behaviour and problem. See Create a LEIA with the AI assistant.
  2. Test. Chat with your LEIA and try the solution editor before any student sees it. See Test a LEIA.
  3. Group and publish. Put the LEIA in an activity, optionally with other LEIAs, and publish it. See Activities.
  4. Replicate. In the Workbench, create a replication of the published activity and configure it. See Workbench overview and Replication settings.
  5. Run. Activate the replication and give students the code or the link. See What students see.
  6. Follow and grade. Watch sessions live, read transcripts, check the automatic evaluation and download a CSV. See Live dashboard and spectating and Results, grading and export.

Before you start​

  • An account in the Designer. Anyone can register, but new accounts get the instructor role, which cannot create behaviours nor enter the Workbench. Ask the LEIA team for the advanced role before you plan a class. The details are in Accounts and roles.
  • A language model key. The AI assistant that builds LEIAs, the supervisor and the code editor widget all need an OpenAI key. Your administrator may have shared system keys with you already. See API keys and models.
  • A modern browser. Voice modes need a microphone and permission to use it.

If you prefer to learn by doing, start with the quick start, which creates a LEIA from an existing one in about ten minutes.
