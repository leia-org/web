API keys and models

Who can do this

Every role can add and manage its own keys. Only administrators can create system keys that are shared with other users.

Why you need a key​

LEIA does not run language models itself. Every conversation, every automatic evaluation and every AI feature of the Designer calls a provider such as OpenAI with a key, and the cost of those calls goes to the owner of the key. This is called bring your own key. You add the key once in the API keys page and then choose it wherever a model is needed.

Your administrator may have shared system keys with your account. They appear in your list with a System chip and you can use them straight away. In that case you can skip the rest of this page until you need a provider of your own.

Supported providers​

ProviderKey typeWhat you getNotes
OpenAIopenaiText conversations, tool calls for widgets, the AI assistant of the Designer, the supervisorRequired for the AI assistant, the supervisor and any LEIA with widgets
Google GeminigeminiText conversations and the avatar and infographic images of a LEIARequired to regenerate images
OllamaollamaOpen models served by an Ollama server you run yourselfNeeds the Base URL of the server
ALMAalmaModels served by the ALMA platform of the University of SevilleNeeds a Base URL and an ALMA key

The list of models offered for each provider is maintained by the platform, so it may change without any action on your part. Anthropic keys are accepted by the form but no model runs with them yet.

Your keys​

Open API keys in the sidebar of the Designer. The Workbench has the same page under API Keys, and both show the same list.

#ItemWhat it shows or does
1Key nameThe description you gave the key.
2ActiveAn inactive key is kept but hidden from every model selector.
3SystemThe key was created by an administrator and shared with you. You can use it but not edit or delete it.
4StarMark as Default. The default key is preselected wherever a key is needed and is assigned automatically to new replications. Only one key can be the default.
5API Key ValueThe key, masked. Nobody can read a key back once it is saved.
6API Key ProviderThe provider of the key.
7Default ModelThe model preselected when this key is used. You can still pick another model of the same provider in each place.
8New API keyOpens the form below.

Keys of your own also show an Edit and a Delete icon.

Add a key​

#FieldWhat it does
1Key Name (Description)A name you will recognise later, for example "My OpenAI key for the autumn course". Required.
2API Key ValueThe secret issued by the provider. Required when creating. When editing, leave it blank to keep the current value.
3API Key TypeThe provider. Changing it clears the model, because models belong to a provider. Required.
4StatusActive or Inactive. Inactive keys are kept but cannot be selected.
5Default ModelThe model preselected wherever this key is used. The list depends on the provider. Required.
6Base URLWhere the provider lives. Only local or self-hosted providers such as Ollama and ALMA need it.
7Management URLOptional link to the provider's dashboard. The Workbench shows it as a Dashboard link next to the model selector so you can check your usage.
8Make this the default API KeyShown only when you already have at least one key. The new key becomes the default one.
9Create KeySaves the key. The provider checks the format of the value, so a key with a typo is rejected here.

Administrators also see Make this a System API Key. A system key is available to every user whose account has system access enabled.

Edit, disable and delete​

  • Edit opens the same form. The value field is empty and the current secret is kept unless you type a new one.
  • To stop a key temporarily, edit it and set Status to Inactive. Replications that used it will show the model as unavailable until you pick another key.
  • Delete asks for confirmation. Any replication still using the key stops working immediately, so change the model of those replications first.

Troubleshooting​

  • The model list is empty in the Workbench. The list only shows models of providers for which you have an active key. Add or activate a key for that provider.
  • "Configure an API key before testing a LEIA". You have no active key at all. Add one or ask your administrator for a system key.
  • "This activity uses widgets, so its tool functions only run on a tool-capable provider". The LEIA has a code editor. Only OpenAI models can call its tools, so choose an OpenAI key.
  • A replication refuses to activate. Every LEIA in it needs a model and a key. Open the LEIA in the replication, pick them and press Save. See LEIA settings in a replication.
