Create a LEIA with the AI assistant

Who can do this

The advanced and admin roles. An instructor can follow every step but Finish LEIA will be refused, because the assistant creates a new behaviour and instructors cannot create behaviours. Instructors should use the quick start instead.

This page follows the creation of a complete LEIA from a one-paragraph description, and explains every control of the design screen on the way. The example is a requirements interview with Helen Park, the manager of a small university library. Expect fifteen minutes the first time.

Before you start​

  • You need an OpenAI key, yours or a system key. The assistant and the supervisor only work with OpenAI. See API keys and models.
  • Decide the scenario in one paragraph. Who the character is, what the student must obtain, what the student must deliver and in which format.
  • Optionally prepare a PDF with a past exercise. The assistant reads it and builds the LEIA from it.

Step 1, the workspace​

Press Design in the sidebar or New LEIA in the library.

#AreaWhat it is for
1Step indicator1 New LEIA is where you build. 2 Review is where you name and finish.
2Activity setupThe widgets of the problem. It stays empty until a problem exists. See Code editor widget.
3AI AssistantThe chat where you describe what you want. The assistant writes the persona, the behaviour and the problem for you.
4Workbench previewA summary of the LEIA being built. Click a card to edit that component. The Test LEIA button lives here.
5Design menuThe three dots. Assistant settings chooses the model and key the assistant uses. Administrators also find Components here, a manual picker of existing personas, problems and behaviours.
6DraftsYour saved drafts. The number counts them.
7Review LEIAGoes to step 2. Enabled once the three components exist and combine without errors.
8Go backLeaves the screen. If you have unsaved work it asks whether to keep a draft.

Assistant settings​

#FieldWhat it does
1ModelThe OpenAI model that writes the components.
2API KeyThe OpenAI key that pays for it. System keys appear here too.

Changing either value starts a new assistant conversation on the server. The settings are remembered with the draft.

Describe the activity​

#ControlWhat it does
1Attach a PDFAttaches one or more PDF files, up to 10 MB each. Other formats are refused. The attached files show as chips above the box.
2Message boxYour brief. Enter sends, Shift+Enter adds a line.
3Send messageSends the brief.

The brief used in this example was

Create a requirements-elicitation activity about a library booking system. The persona is Helen Park, the manager of a small university library. She wants a web application so students can book study rooms and borrow books. Students must interview Helen to discover the requirements and deliver a UML class diagram in Mermaid syntax as their solution.

A good brief names the character, the goal of the student, the deliverable and its format. The assistant does the rest. It can also read the current components, reuse an existing persona from the library and suggest a title.

Watch the assistant work​

#ItemMeaning
1Confirmation linesA green line appears for each component the assistant wrote, with the name it chose. ✓ Problem applied, ✓ Behaviour applied, ✓ Persona applied and ✓ LEIA title suggested.
2Ready to testThe chip in the preview turns from Draft to Ready to test when the three components combine without errors.
3TitleThe title suggested by the assistant. Edit it freely. Once you type your own title the assistant stops suggesting.
4Add widgetAppears in Activity setup as soon as a problem exists.
5Test LEIAStarts a test conversation. The draft is saved first.
6Review LEIAGoes to step 2.
A new problem clears the behaviour

Each time the assistant applies a new problem, the current behaviour is removed, because a behaviour must match its problem. If the assistant writes the behaviour before the problem, the preview shows the behaviour card empty and the buttons stay disabled. Simply ask "Apply the behaviour again for this problem" and the assistant rewrites it.

The preview panel​

#ItemWhat it does
1Status chipDraft or Ready to test.
2TitleThe name proposed for the LEIA. You confirm or change it in step 2.
3Persona cardFull name, personality and description. Click to open the persona editor.
4Behaviour cardRole, process and description. Click to open the behaviour editor.
5Problem cardSolution format, number of widgets, description and details. Click to open the problem editor.
6Test LEIAOpens the test chat with the current components.

Every field of the three editors is explained in Persona, Problem and Behaviour fields. If a component cannot be combined with the others, a red message under the title explains why, for example a constraint of the problem that the behaviour does not satisfy.

Refine with the assistant or by hand​

You can keep talking to the assistant. "Make Helen more reluctant to give details", "add a non-functional requirement about accessibility", "change the solution format to plain text". Each request rewrites the component concerned and the preview updates.

You can also click a card and edit the fields yourself. Edited components are marked as new, so a new persona, problem or behaviour is created when you finish, even if the assistant reused an existing one.

Test before saving​

Press Test LEIA in the preview panel. The chat opens with your components and you come back with Continue Configuration. See Test a LEIA.

Drafts and autosave​

Everything you do on this screen is saved as a draft on the server about one second after each change. The draft holds the components, the names, the labels, the assistant conversation, its settings and the supervisor settings.

When you press Go back the dialog Keep this LEIA draft? offers two choices.

#ButtonWhat it does
1Continue editingStays on the screen.
2Save draft and leaveSaves and returns to the library.

Closing the browser tab shows the browser's own "leave page" warning. The draft is already saved, so leaving is safe.

The Continue drafts page lists every draft.

#ItemWhat it does
1Draft cardTitle, last update, the step you were in (New LEIA or Review), the components already created and the number of assistant messages saved.
2ContinueReopens the design screen exactly where you left it.
3DeleteRemoves the draft after a confirmation.
4New LEIAStarts a fresh LEIA.
5RefreshReloads the list.

The Drafts button of the design screen opens the same list in a dialog, with Continue and Delete on each entry. Deleting the draft you are editing clears the workspace.

Step 2, review and finish​

Press Review LEIA.

#FieldWhat it does
1New LEIA nameThe name of the LEIA in the library. It must be unique. The screenshot shows another LEIA of this guide, docs-demo-secret-word.
2LabelsPick existing labels or type a new name and press Enter. A new label opens a small dialog with its colours and is created when you finish.
3Supervisor (AI background monitor)The second AI that watches the conversation. Off by default. See The supervisor.
4EnabledTurns the supervisor on and reveals its settings.
5Behaviour nameThe name of the behaviour component. Prefilled by the assistant.
6Problem nameThe name of the problem component.
7Persona nameThe name of the persona component.
8Component codeA read-only JSON preview of each component, for a last check.
9PreviousBack to step 1.
10Finish LEIACreates everything.

Administrators see two more controls, a LEIA visibility selector that makes the LEIA public and a Visibility selector on each component.

The Code preview accordion of each component shows the exact JSON that will be saved.

What Finish does​

  1. Checks that the LEIA name and the names of new components do not exist yet. "Name already exists" means you must change that name.
  2. Creates the pending labels.
  3. Creates every component that is new or edited. Unchanged components taken from the library are reused.
  4. Creates the LEIA with version 1.0.0 and the supervisor settings if enabled.
If Finish fails with "Failed to create problem resource"

The server refuses a problem whose Initial Solution is empty text, and the assistant sometimes leaves it empty. Go back to step 1, open the problem, write something in Initial Solution, save and finish again. Removing the initialSolution line in the Code Editor tab is not enough, the visual editor sends the field as empty text anyway. Your work is kept in the draft.

#ButtonWhat it does
1Go to LEIAsReturns to the library.
2Add to ActivityAdds the new LEIA to an unpublished activity, or to a new one. See Activities.
3Quick ReplicationCreates an activity and a Workbench replication with the new LEIA and opens the replication in a new tab.

Instructors only see Go to LEIAs.

What to do next​

  • Test the LEIA from the library with the model your students will use. See Test a LEIA.
  • Put it in an activity and publish it. See Activities.
  • Open the Workbench and create a replication. See Workbench overview.
