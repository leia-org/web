What students see

Who can do this

Students need no account. Teachers can walk the same path with the Demo / test link of a replication, which creates a throwaway identity that is excluded from the results.

This page follows a student from the join code to the end of the session, so you know what to explain in class and what each switch of the replication changes on their screen.

Join​

Students open workbench.leia.ovh or the Student link you copied from the replication, which prefills the code.

#Field or buttonWhat it does
1EmailThe identifier of the student. It is not verified and never contacted. The same address must be used to resume a session.
2Replication codeThe code of the replication, the same for the whole class.
3Start sessionCreates the session, or resumes an unfinished one with the same email.

What can go wrong at this step.

MessageCause
"Please fill in all fields"A field is empty.
The code is unknownA typo in the code, or the replication was deleted.
The replication is not activeThe Active switch of the replication is off.
The session was already completedThe student finished and the replication is not Repeatable.

In an activity with several LEIAs and Single LEIA assignment, each new student receives the LEIA with the fewest sessions so far.

Consent​

When Data Usage Consent Acceptance is enabled in the replication, the first thing the student sees is the consent dialog with your message and two buttons, No, I do not consent and Yes, I consent. The choice is recorded with the session and cannot be skipped. With automatic removal enabled, a student who declines still does the activity, but the conversation is deleted afterwards. See Data Usage.

Instructions​

#ItemWhat it is
1StatementThe Description of the problem.
2Continue TaskCloses the dialog and starts the conversation. In voice modes the microphone is unmuted at this moment.

The chat​

#ControlWhat it does
1TimerCounts down the Duration of the replication. It turns orange in the last minute and red at zero. Shown only when a duration is set.
2NotesA floating notepad saved in the student's browser only. It is not sent to you.
3InstructionsReopens the statement. A Guidance button appears next to it when Show during exercise is on and the LEIA has a student infographic.
4Go to Editor, Finish Session or Send SolutionThe main button. Go to Editor opens the solution editor when Ask for student solution is on. Finish Session ends the session when no solution is asked for. Send Solution appears instead when the LEIA has a code editor widget. The button stays disabled until the student has sent a first message.
5Message boxEnter sends, Shift+Enter adds a line.
6SendSends the message.

Before the first message a Try typing hint (1) suggests an opening line taken from the behaviour's Tooltip. Click to copy to input pastes it into the box.

The LEIA answers in the Language of the replication. If an answer is slow a Retry button appears in the LEIA's bubble. When the student scrolls up, a New messages button brings them back down.

Voice modes​

With Audio mode set to Luke, the chat is replaced by a full-screen stage with the character's avatar, a microphone button and a Show transcript panel. With Legacy (OpenAI Realtime), a floating card shows Mute Microphone, a visualiser and the connection state. In both cases the student speaks, the LEIA answers with a voice, and the text of the exchange is saved as a transcript unless you enabled Hide audio transcription. See LEIA settings in a replication.

Widgets​

#ItemWhat it is
1EditorThe code editor configured in the problem, with the statement and the starter code.
2Test strip"not run yet" until the LEIA runs the tests, then the number of passed tests and the failures with the expected and obtained values.
3Send SolutionSends the content of the editor as the solution and ends the session.

There is no run button. Students ask the LEIA to check their code, the LEIA runs the tests and answers with hints, as Ada does in the example after four of five tests passed.

MultiLEIA​

Each LEIA message carries the name of the character who speaks, Helen (1) and Omar (2) in the example. After one student message one or more characters answer, up to the limit set in the activity. If a character fails to answer, an amber notice says that the round ended early and the conversation continues.

Supervisor nudge​

When the supervisor is enabled with nudges, the student may receive a short amber card (1) with a coaching message. It can be dismissed. The flags themselves never reach the student.

Submit a solution​

#ControlWhat it does
1EditorThe solution in the Solution Format of the problem. It starts with the Initial Solution, or with a sample diagram for Mermaid when there is none. For LEIAs with the code editor widget the code is carried over.
2PreviewLive rendering of diagrams, Markdown and HTML, syntax colours for the rest.
3Send SolutionAsks for confirmation, then submits.
4TimerThe same countdown as in the chat. Notes is available here too.

The confirmation says "This action will conclude the problem and you will not be able to continue working on it". Conclude Problem (1) submits, Cancel (2) returns to the editor.

The timer and the editor

If the time runs out while the student is in the editor, the session is closed without submitting the editor content. Tell students to submit a minute before the end.

After submitting​

#ItemWhat it is
1EvaluationThe automatic evaluation, when Automatic evaluation is on. Otherwise a simple "Solution submitted successfully".
2Conversation viewer linkA link to a read-only view of the conversation, valid for one year, with a Copy Link button. Students can keep it or hand it in.
3HomeReturns to the login page.
4Open FormOpens the questionnaire. Shown only when the replication has an External form URL.

Once the dialog is closed the editor shows the reference Problem Solution next to Your Solution, so the student can compare.

When no solution is asked for, Finish Session shows a simpler Session Completed dialog with the same Home and Open Form buttons.

A student who enters the code again after finishing is stopped at the login form with the message "User has already finished this replication. Replication is not repeatable." (1). If the replication is Repeatable, entering the code again starts a fresh session instead. A student who reopens the address of a finished chat sees Session Already Completed with a countdown back to the login page.

What students never see​

  • The Details, Solution and Evaluation Prompt of the problem, except the solution after submitting.
  • The supervisor flags.
  • The infographic with the solution.
  • Other students' sessions.
