LEIA settings in a replication

Who can do this

The owner of the replication, administrators and anyone with its share link.

The LEIAs section of a replication lists every LEIA of the activity. Each one has its own page with the switches that decide what the student does at the end, which model plays the character and whether the student talks or types. Changes to the two Conversation switches and to the infographic options are saved at once. Changes in the Runner block need the Save button.

The LEIA page​

#ControlWhat it does
1View contentOpens a drawer with the persona, the behaviour and the problem of the LEIA, and a Raw JSON tab.
2Test sessionStarts a session for you with this LEIA, in a new tab. Test sessions skip the consent dialog and never appear in the results. If the runner block has unsaved changes you are asked to save first.
3Mode and SessionsThe mode of the LEIA in the activity (standard or transcription) and how many sessions it has run.
4Ask for student solutionWhen on, the student's main button becomes Go to Editor (or Send Solution with a code widget) and the session ends with a submission. When off, the student simply presses Finish Session.
5Automatic evaluationWhen on, the submission is graded by the language model against the problem's solution and the student sees the evaluation at once. Requires the previous switch.
6Show during exerciseLets the student open the student infographic from a Guidance button in the chat. Disabled when the LEIA has no infographic.
7Instructor solutionView solution opens the infographic with the solution, for you only.

The infographics are generated in the Designer, from the View dialog of the library. When they are missing the page says "No infographic is available for this LEIA. Open it in Designer and generate the infographic assets before configuring them here."

In a MultiLEIA activity a banner MultiLEIA activity summarises the flow and offers Test MultiLEIA, which starts a session with every LEIA at once.

Runner​

#ControlWhat it does
1ModelThe language model that plays this LEIA. The list only contains models of providers for which you have an active key. The icon shows the provider. A model that is no longer available is marked and must be replaced.
2Audio modeNone for a written chat, Legacy (OpenAI Realtime) or Luke for a spoken conversation. See Voice.
3Hide audio transcriptionIn voice modes, hides the text of the conversation from the student. The transcript is still saved for you.
4Luke providerThe engine of the Luke mode, OpenAI or Gemini.
5Luke voiceThe voice, with a play button to hear a sample. The voices are filtered by the pronouns of the persona.
6SaveWrites the runner block. "Please select a valid model and API key" means a field is missing.
7ResetDiscards the unsaved changes.

An API key selector appears under Model when more than one of your keys fits the chosen model. Otherwise the only compatible key is used, which is the case in the screenshot. The default key is marked (Default). Next to Model two links appear, Dashboard when the key has a management URL and Manage Keys, which opens the API keys page.

When the activity has widgets the block warns "This activity uses widgets, so its tool functions require a tool-capable provider. Currently, only OpenAI models are available." and the model list shrinks accordingly.

If you leave the page with unsaved runner changes, or press Test session or the Active switch, a dialog Unsaved Changes asks whether to save first. If a saved model disappears from the catalogue, a dialog Model not available lists the LEIAs to fix.

Voice conversations use the platform's own provider keys, not yours. The persona answers in the language of the replication. Voice is not available in MultiLEIA activities.

Which model to choose​

  • The model used while you tested the LEIA in the Designer is the safest choice. Behaviours tuned for one model can behave differently on another.
  • Only OpenAI models can use the code editor widget and the supervisor.
  • Small, fast models keep the conversation lively. Reserve larger models for LEIAs that must reason about a complex solution.
  • A replication cannot be activated while any LEIA lacks a model or a key.
